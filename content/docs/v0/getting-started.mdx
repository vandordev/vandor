Install `vx`, scaffold a project, and review the generated structure before wiring adapters.

## Install the CLI

Use any placeholder install flow that matches your environment.

```bash
brew install vandor/tap/vx
vx version
```

If the command is available, you are ready to scaffold the first service.

## Initialize a service

Start with a simple backend project. In `v0`, the workflow is intentionally lightweight and favors a smaller generated surface area.

```bash
vx init billing-service
cd billing-service
```

This should create a minimal project shell with application, domain, and adapter boundaries separated from the start.

## Generate a first bounded context

Once the project exists, generate a context that will hold the first business capability.

```bash
vx generate context billing
```

This command is expected to create an isolated domain boundary where entities, repositories, and use-case wiring can evolve without collapsing into one package.

## Inspect the generated structure

After generation, the project may look similar to this:

```text
internal/
  domain/
    billing/
  app/
    billing/
  adapter/
    http/
```

At this stage, treat the structure as scaffolding only. The important part is that domain code, application flow, and delivery concerns are no longer mixed together.

## Add the first adapter

To expose the new context, generate a delivery layer.

```bash
vx generate adapter http
```

The HTTP adapter can stay thin while use cases remain in the application layer and business rules remain in the domain core.

## Next steps

- Add your first entity and repository interface inside `internal/domain/billing`
- Implement one use case in `internal/app/billing`
- Connect transport handlers in `internal/adapter/http`
- Continue exploring the rest of the dummy docs for later versions
